# INSANITY

러브크래프트풍 텍스트 로그라이크. 서울 2033처럼 매 판 인카운터가 다른 순서로 나오고, 죽으면 처음부터 다시 시작합니다.
이 저장소에는 **게임 엔진/화면**과 인카운터를 채워 넣기 위한 **에디터**가 들어 있습니다.

```bash
npm install
npm run dev
```

- 게임: http://localhost:5173/
- 에디터: http://localhost:5173/editor.html

`content/` 폴더의 예시 인카운터 10개(흑포 기행)는 기능 시연용입니다. 에디터에서 지우고 새로 채우면 됩니다.

## 게임 규칙

| 항목 | 내용 |
| --- | --- |
| 체력 | 칸 단위 (기본 3칸). 0이 되면 사망 엔딩 |
| 정신력 | `현재 / 최대` (기본 100/100). 사건에 따라 현재값뿐 아니라 **최대값도 깎일 수 있음**. 최대값이 줄면 현재값도 그 이하로 깎임. 0이 되면 광기 엔딩 |
| 아이템 | 개수가 있는 소지품 (플레이어에게 보임) |
| 능력 | 있거나 없는 특성 (플레이어에게 보임) |
| 플래그 | 플레이어에게 보이지 않는 숫자 변수. 이야기 진행 상태 기억용 |
| 저장 | 매 선택마다 자동 저장. 엔딩에 도달하면 저장이 지워짐 (영구 죽음) |

정신력이 낮아지면 화면이 어두워지고 흔들립니다.

### 선택지

- **요구 조건**: 선택지 앞에 `[권총]`처럼 표시. 충족하면 초록, 아니면 빨강이고 고를 수 없음.
- **표시 조건**: 만족하지 않으면 선택지가 아예 안 보임 → "특정 능력이 있으면 생기는 선택지".
- **조건에 따른 결과 분기**: 요구 조건 없이도, 같은 선택지의 결과가 능력/아이템/수치에 따라 달라짐. 위에서부터 처음 맞는 분기가 선택되고, 마지막 "그 외의 경우"가 기본값.
- **확률 결과**: 한 분기 안에 결과를 여러 개 두면 가중치대로 무작위.
- **조건부 문단**: 조건을 만족하면 본문에 덧붙는 서술.
- 선택지가 전부 빨간색이라 고를 게 없으면 "어쩔 수 없다 (계속)" 버튼이 나와 막히지 않습니다.

## 출현 규칙 (선후관계)

인카운터마다 출현 방식을 정합니다.

| 방식 | 설명 | 용도 |
| --- | --- | --- |
| 랜덤 | 조건을 만족하면 랜덤 풀에 들어가 가중치에 따라 뽑힘 | 대부분의 사건 |
| 후속 전용 | 랜덤으로는 안 나오고, 다른 인카운터 결과의 **인카운터 예약** 효과로만 등장 | 선택에 따라 이어지는 사건 |
| 고정 순번 | n번째 인카운터로 등장 | 프롤로그, 피날레 |

랜덤/고정 인카운터에는 추가로:

- **선행 인카운터 + 간격**: A를 겪은 뒤에만 등장. "사이에 최소 a ~ 최대 b개"는 A와 이 인카운터 사이에 끼어드는 다른 인카운터 수. 최대값에 도달하면 강제로 등장.
- **등장 구간**: n번째 ~ m번째 인카운터 사이에서만 (초반/후반 전용 사건).
- **추가 출현 조건**: 아이템/능력/플래그/수치/다른 인카운터를 겪었는지.
- **반복**: 기본은 한 판에 한 번. 반복 가능하게 하고 재등장 간격을 줄 수 있음.

자주 쓰는 패턴:

| 원하는 것 | 설정 |
| --- | --- |
| 아무 때나 나오는 사건 | 랜덤, 조건 없음 |
| A 바로 다음에 반드시 B | B의 선행 인카운터 = A, 간격 0~0 (또는 A 결과에 "B 예약, 0개 뒤") |
| A 다음에 순서대로 나오지만 사이에 랜덤 사건 2~5개 | B의 선행 = A, 간격 2~5 |
| A에서 특정 선택을 했을 때만 이어짐 | B를 후속 전용으로 두고, A의 그 결과에만 "B 예약" 효과 |
| A에서 한 선택을 나중에 기억 | A 결과에서 플래그 설정 → B의 출현 조건/분기에서 플래그 검사 |
| A와 B 중 하나만 | B의 출현 조건에 "A 겪지 않음" (반대도) |

다음 인카운터 선택 우선순위는 **예약 → 고정 순번 → 강제(최대 간격 도달) → 랜덤**입니다.
출현 가능한 인카운터가 하나도 없으면 "정적" 엔딩이 나오므로, 반복 가능한 채움용 인카운터를 몇 개 두는 것을 권장합니다.

## 에디터

| 탭 | 내용 |
| --- | --- |
| 인카운터 | 출현 설정, 페이지/선택지/분기/결과/효과 편집. "▶ 여기서 테스트"로 해당 인카운터부터 플레이 |
| 흐름도 | 인카운터 사이의 선후관계(선행, 예약, 조건, 상태 의존)를 그래프로 표시 |
| 아이템·능력·플래그 | 정의 목록. id를 바꾸면 쓰이는 곳이 모두 함께 바뀜. 사용처 확인 |
| 엔딩 | 사망/광기/정적(기본)과 직접 만든 엔딩 |
| 시작 설정 | 게임 제목, 도입부, 시작 체력/정신력/아이템/능력 |
| 검증 | 없는 페이지/아이템 참조, 도달할 수 없는 페이지, 등장할 방법이 없는 인카운터, 선행 관계 순환 등 |
| 시뮬레이션 | 무작위로 수천 판을 돌려 인카운터별 출현률/처음 나오는 순번/엔딩 분포 확인 |

- **저장** (Ctrl+S): `content/` 폴더에 바로 기록합니다. 저장 전 작업은 브라우저에 자동 백업되어, 창을 닫아도 다음에 복구할 수 있습니다.
- **되돌리기/다시** (Ctrl+Z / Ctrl+Shift+Z).
- **▶ 테스트 플레이**: 저장하지 않은 내용으로 새 탭에서 실행합니다. 테스트 탭이 열려 있으면 에디터에서 고친 내용이 바로 반영됩니다. 테스트 화면의 디버그 패널(`` ` `` 키)에서 체력/정신력/아이템/능력/플래그를 바꾸거나, 각 인카운터가 지금 왜 나올 수 없는지 확인하고 바로 시작할 수 있습니다.
- 아이템/능력/플래그/인카운터/엔딩 선택 칸의 맨 아래 **"＋ 새 … 만들기"**로 작업 도중 바로 만들 수 있습니다.
- 본문 표기: 줄바꿈 = 문단, `*기울임*`, `**굵게**`.
- 게임 단축키: 숫자 1~9 = 선택지, Space/Enter = 계속.

## 콘텐츠 파일

```
content/
  game.json                 메타, 시작 상태, 아이템/능력/플래그/엔딩 정의, 인카운터 목록 순서
  encounters/<id>.json      인카운터 하나당 파일 하나
```

에디터 없이 JSON을 직접 써도 됩니다. 빠진 필드는 기본값으로 채워지고, 아래처럼 줄여 쓸 수 있습니다.

```jsonc
{
  "id": "dark_alley",                         // 영문/숫자/_/- (파일 이름)
  "title": "어두운 골목",
  "spawn": { "mode": "random", "weight": 10, "minTurn": 3 },
  "nodes": [
    {
      "id": "start",
      "text": "골목 끝에서 무언가 젖은 소리를 내며 움직인다.",
      "choices": [
        {
          "text": "총을 쏜다",
          "require": [{ "type": "item", "id": "pistol" }],          // 조건 배열 = 모두 만족
          "outcomes": [{ "text": "총성이 울렸다.", "effects": [{ "type": "stat", "stat": "sanity", "value": -3 }] }]
        },
        {
          "text": "주문을 왼다",
          "showIf": [{ "type": "trait", "id": "forbidden_lore" }],  // 능력이 있어야 보임
          "outcomes": [{ "text": "그것이 물러났다." }]
        },
        {
          "text": "다가간다",
          "branches": [                                              // 같은 선택지, 능력에 따라 다른 결과
            { "condition": [{ "type": "trait", "id": "iron_will" }], "outcomes": [{ "text": "버텼다." }] },
            {
              "condition": null,
              "outcomes": [                                          // 확률 결과 (가중치 3:1)
                { "weight": 3, "text": "눈이 마주쳤다.", "effects": [{ "type": "stat", "stat": "maxSanity", "value": -5 }] },
                { "weight": 1, "text": "물렸다.", "effects": [{ "type": "stat", "stat": "hp", "value": -1 }], "next": "bitten" }
              ]
            }
          ]
        }
      ]
    },
    { "id": "bitten", "text": "상처가 이상하게 차갑다.", "choices": [] }
  ]
}
```

| 조건 `type` | 필드 |
| --- | --- |
| `item` | `id`, `op`(기본 `>=`), `value`(기본 1) |
| `trait` | `id`, `has`(기본 true) |
| `flag` | `id`, `op`, `value` |
| `stat` | `stat`(`hp`/`maxHp`/`sanity`/`maxSanity`), `op`, `value` |
| `turn` | `op`, `value` — 현재 몇 번째 인카운터인지 |
| `seen` | `encounterId`, `has` — 이번 판에서 겪었는지 |
| `all` / `any` | `items`: 조건 목록 (모두 / 하나라도) |

| 효과 `type` | 필드 |
| --- | --- |
| `stat` | `stat`, `value`, `valueMax`(있으면 value~valueMax 무작위) |
| `item` | `id`, `value`(음수 = 잃음) |
| `trait` | `id`, `has`(false = 상실) |
| `flag` | `id`, `mode`(`set`/`add`), `value` |
| `queue` | `encounterId`, `delay`(0 = 바로 다음) |
| `ending` | `endingId` |

`spawn` 필드: `mode`(`random`/`triggered`/`fixed`), `weight`, `repeatable`, `cooldown`, `minTurn`, `maxTurn`, `fixedTurn`, `after: [{ encounterId, minGap, maxGap }]`, `condition`.

## 명령어

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 게임 + 에디터 개발 서버 |
| `npm run content` | `content/` 파일을 표준 형식으로 정리(빠진 필드/id 채움)하고 검증 결과 출력 |
| `npm run content:check` | 검증만 (오류가 있으면 실패) |
| `npm run content -- --import 파일.json` | 에디터 "내보내기" 파일로 `content/`를 덮어씀 |
| `npm test` | 엔진 테스트 |
| `npm run build` | `dist/`에 정적 사이트 빌드 (게임 + 에디터). 빌드된 에디터는 파일 저장 대신 내려받기만 가능 |

## 코드 구조

```
src/engine/     게임 규칙 (UI와 무관한 순수 TypeScript)
  types.ts        데이터 모델
  run.ts          한 판의 진행 (선택, 계속, 엔딩)
  scheduler.ts    다음 인카운터 선택 규칙
  conditions.ts / effects.ts / describe.ts
  content.ts      JSON 정규화, 파일 분할/결합
  validate.ts     검증
  simulate.ts     시뮬레이션
src/game/       게임 화면 (React)
src/editor/     에디터 (React)
tools/          개발 서버 저장 API, content CLI
```
